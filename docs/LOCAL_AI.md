# 網站內的三青 AI 助理

目前是**本機假資料整合版**，尚未部署到 GitHub／Vercel，也沒有連接或修改正式資料庫。
這份副本來自 `Sstanly990506-cyber/-`，本機開發分支是 `codex/local-ai-integration`。
保留原有 Python／Flask 相容後端與原生 JavaScript，沒有改成 Next.js，也不需要 Docker。

## 啟動與停止

請保留以下兩個資料夾在同一層：

```text
outputs/
  sanqing-local-ai/       原本的 Python、Ollama 模型設定與文件庫
  sanqing-website-ai/     這次的網站整合副本
  .sanqing-website-ai-demo-v1/  啟動後產生的假資料，不在網站公開目錄或 Git 儲存庫內
```

1. 在 `sanqing-website-ai` 資料夾雙擊 `start-ai.cmd`，或在這裡開啟 PowerShell 執行 `./start-ai.cmd`。
2. 開啟 `http://127.0.0.1:4173`，按「進入假資料示範（不需密碼）」。不需要輸入真實帳號密碼。
3. 按右下角「三青 AI 助理」。
4. 停止：在啟動視窗按 `Ctrl+C`，或在助理面板按「停止本機示範」並確認。
5. 重新開機後重做第 1–3 步即可。沒有安裝自動開機服務，也不會修改系統執行原則。

如果 4173 已被使用，可執行 `./start-ai.cmd --port 4174`，網址也改成 4174。
`start-ai.ps1` 是選用包裝；若 PowerShell 禁止執行腳本，使用 `.cmd` 即可，不需管理員權限。

示範登入只存在於專用啟動器啟用的本機假資料模式。一般 `app.py`／Vercel 入口不會啟用示範登入或 AI。
示範模式只開放唯讀 API、AI 對話與經確認的備註修改。其他原網站表單、LINE、雲端辨識等操作會被拒絕；不要把它當正式網站使用。

## 三種用途

| 模式 | 可以做什麼 | 證據與限制 |
| --- | --- | --- |
| 一般聊天 | 招呼、一般問題、整理文字、程式說明 | 不讀資料庫；不是公司事實來源。保留最多兩輪短對話，清除／登出即丟棄 |
| 文件查詢 | 查詢 `sanqing-local-ai/data/private/` 已建立索引的文件 | 沿用檔名、頁碼或行號。沒有足夠證據時拒答。目前僅管理員可用 |
| 網站資料 | 查詢工單、客戶名稱與類別、庫存 | 按登入帳號的既有模組權限；固定欄位、最多 5 筆，顯示資料 ID 與版本。不是完整統計 |

網站資料模式先選種類，再輸入關鍵字。例如：工單輸入 `DEMO-001`；庫存輸入 `透明膜`；輸入「最近」會列出最近資料。
這是關鍵字搜尋，不是任意自然語言分析器；不支援完整財報、任意 SQL、跨表統計或自行操作整個網站。
資料庫的結果由程式組合，不交給語言模型解讀或執行。這可減少編造與提示注入風險。

文件查詢可試「QX-17 是什麼意思？」；來源應為完全虛構的測試文件。
一般聊天可試「你好」；這個招呼不用載入模型。
小型 1.5B 模型在推理、複雜程式碼、中文表達方面仍有限制，不等同大型雲端模型。

## 修改資料：目前只開放庫存備註

管理員在「網站資料 → 庫存」查到資料後：

1. 按「修改備註」，輸入新的非空白備註。
2. 按「先看修改預覽」。此時**尚未寫入**。
3. 核對原文、新文及警告，在 120 秒內按「確認修改這筆備註」。
4. 同一筆備註與稽核紀錄會一起儲存；稽核包含操作者、原文、新文與時間。

預覽綁定目前登入，只能使用一次；若別人已修改資料、預覽逾期或重複確認，就拒絕寫入。
確認請求無法更換原先預覽的內容。PostgreSQL 路徑使用參數化查詢、資料列鎖定與交易；本機 JSON 路徑使用鎖與同一檔案的原子替換。
不開放 AI 刪除、清空、建立表格、修改庫存數量、改金額、改權限或發送 LINE。
若網路中斷導致「結果未知」，請先重新查詢與查看稽核紀錄，不要盲目重送。

## 記憶體與本機安全

- 使用原本的可攜式 Python，不需要再安裝 Flask、PostgreSQL、Docker 或向量資料庫服務。
- 網頁後端使用 Python 標準函式庫，固定綁定 `127.0.0.1`。助理只連 `127.0.0.1:11434` 的 Ollama。
- 模型問答前要求至少 1.5 GiB 可用實體記憶體；不足時明確拒絕載入，但招呼與網站資料仍可使用。此檢查不是長期峰值記憶體保證。
- 一次只處理一個模型請求，Ollama 設定最多載入一個模型。嵌入與文字生成順序執行；回答後停止本次啟動的 Ollama 與其模型工作程序。
- 若 Ollama 已被其他工作啟動，請先結束終端機聊天或 Ollama 應用程式；本整合不會接管或強制關閉其他工作。
- 示範子程序不繼承資料庫／API 憑證環境設定，也不載入 `.env`。新助理沒有雲端 AI 備援。
- 示範後端阻擋非 loopback 的 socket 連線；前端限制同來源網路請求。沒有修改防火牆或路由器，也沒有開設隧道。
- API 檢查 Host、Origin、登入憑證、JSON 類型與請求大小；回答設為不可快取。靜態檔案不提供 `.git`、`.env`、程式後端、私有資料、金鑰、runtime 或索引。
- 回答一律當純文字呈現，不執行文件／答案中的 HTML 或 JavaScript。不讓模型呼叫寫入工具。
- 輸入／輸出做常見憑證樣式檢查，但無法辨識所有秘密。不要貼上任何密碼、API Key、憑證或真實客戶資料。
- 既有網站登入使用簽章 token 中的權限快照；正式上線前應增加伺服器端 session 撤銷／權限即時更新。本機示範 session 30 分鐘到期。

## 匯入文件

沿用 `sanqing-local-ai` 的 README 與 `import-docs.ps1`，不要把文件放進網站目錄。
支援 `.txt`、`.md`、文字型 `.pdf`；掃描圖片 PDF 不會自動 OCR。
先停止模型聊天再匯入，避免兩個工作同時載入模型。
目前只使用完全虛構的測試文件。真實文件需由你確認分類、去識別與存取權限後再處理。
未建立文件分級前，文件模式只提供管理員。

## 測試

在網站資料夾執行：

```powershell
./start-ai.cmd --test
```

測試使用隔離暫存資料夾，清除繼承的敏感環境設定，阻擋外部網路。不連正式資料庫、不呼叫外部 AI。
涵蓋原網站回歸測試、權限、來源、找不到資料、提示不被執行、敏感文字、單一模型鎖、修改預覽／確認／過期／重播／衝突、PostgreSQL 交易 SQL 的模擬測試與實際 loopback HTTP。
Flask 是選用依賴，未安裝時對應測試會明確跳過；本機執行使用已測試的標準函式庫 HTTP 伺服器。

網站啟動後，可以使用同層的 Python 執行唯讀煙霧測試：

```powershell
../sanqing-local-ai/.runtime/python/python.exe -B tools/smoke_local_ai.py
```

加上 `--model` 才測試真實文件生成；需要足夠記憶體及已安裝模型。
基本煙霧測試只產生修改預覽，**不提交修改**。實際寫入僅發生於隔離單元測試或你按下確認時。

## 正式網站的下一步與尚未驗收項目

目前未推送 GitHub、未部署 Vercel、未連正式 DB、未安裝服務，也沒有改動原本網站資料。
此版本的安全啟動器故意不能連正式 DB；正式資料接入需另外做部署設定、備份／回復演練及整合測試。
PostgreSQL 路徑目前只有模擬測試，不能視為正式資料庫驗收通過。

`127.0.0.1` 只代表「正在執行程式的那台電腦」。Vercel 上的 `127.0.0.1` 不是你的 Windows 電腦。
因此不能只把這份程式推到 Vercel，就讓雲端網站呼叫你電腦裡的 Ollama。
維持完全本機限制時，建議在同一台 Windows 同時開網站與 AI；其他同事的電腦不能連這個 loopback 位址。
若你希望公司其他電腦或 Vercel 正式站使用，需要另行決定並授權內網／網路架構；本次沒有擅自公開服務。

模型真實生成仍需可用記憶體足夠時複驗。需人工驗收：實際斷網、瀏覽器完整互動、工作管理員長時間記憶體觀察，以及重新開機後啟動。
