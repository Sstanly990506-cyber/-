# 正式網站＋本機三青 AI（第一版）

正式網站：<https://omega-ten-20.vercel.app/>。
網站與資料庫維持原部署。語言模型、向量索引與私有文件仍在你這台 Windows；不使用外部 AI。
第一版僅管理員可見 AI 面板，只有安裝並啟動本機助理的這台電腦能使用模型。沒有開放區域網路或路由器連接埠。

## 每次使用

1. 在 `sanqing-website-ai` 雙擊 `start-companion.cmd`。請保留同層 `sanqing-local-ai` 與其原有 Python／模型。
2. 在正式網站用自己的帳號登入，不要把密碼或金鑰貼給 AI。
3. 按右下角「三青 AI 助理」→「連接這台電腦」。若瀏覽器詢問本機／區域網路連線權限，只對上述確定的正式網址允許。
4. 按「開啟本機配對頁」，核對帳號和六位配對編號後，按「編號一致，同意這次配對」。編號只是用來核對請求，不是登入密碼。
5. 回到正式網站，看到「已連接」後即可提問。授權最長 20 分鐘；登出、重新整理、重啟或到期後，重新配對即可。

本機控制頁固定為 <http://127.0.0.1:4175/>。它只提供配對、解除與停止，不讀取你的網站密碼或資料庫憑證。
只同意自己剛剛在正式網站發起的配對。新的配對會中斷舊的配對。
瀏覽器必須支援並允許安全的本機連線；若內建瀏覽器拒絕，使用已更新的 Chrome 或 Edge。不要停用瀏覽器安全機制或安裝隧道。
Chrome 的權限行為參考：[官方本機連線說明](https://developer.chrome.com/blog/local-network-access)。

## 可以做什麼

- 一般聊天：問題與最近兩輪短對話直接送到本機，不送進 Vercel API。模型不會查正式資料庫。
- 文件查詢：只查原本 `sanqing-local-ai/data/private/` 已匯入的文件庫，回答附檔名、頁碼或行號；沒有證據就說找不到。第一版文件未分級，所以只開放管理員。
- 網站資料：經網站原有登入權限查工單、客戶名稱／類別、庫存，最多 5 筆並附資料 ID／版本。輸入編號、名稱、品項或「最近」，不是任意 SQL 或完整統計。
- 庫存備註：查出庫存後，先預覽原文與新文，再由你確認；只更新這筆備註，並同時留下稽核紀錄。沒有刪除、改金額、改數量或改權限工具。

網站資料查詢及備註修改需要正式網站網路連線。文件與聊天的運算在本機，但本整合版仍需向正式網站驗證短期授權，所以不是全程斷網模式；完全離線聊天仍用原本 `sanqing-local-ai/start.cmd`。
本機文件答案會顯示在正式網站的瀏覽器頁面，因此你是在信任這個正式網站的前端程式；新增程式不將這些內容上傳或記錄到網站後端。

## 記憶體與停止

目前使用的 1.5B 模型能力有限。系統可用記憶體低於 1.5 GiB 時，不載入模型，避免拖垮 8 GB 電腦；招呼與網站資料不需要載入模型。
請先關閉不用的程式，不要同時開 Ollama 的其他模型工作。遇到記憶體不足不需要重裝。
模型一次只處理一個問題；回答完成後停止本次啟動的 Ollama 工作程序並釋放模型。
停止：在啟動視窗按 `Ctrl+C`，或在本機控制頁按「停止本機 AI」。不會刪除文件或資料。
重新開機後雙擊同一個 `start-companion.cmd` 即可；沒有設定自動開機或管理員服務。

## 安全邊界

- 本機助理只綁 `127.0.0.1:4175`，Ollama 只綁 `127.0.0.1:11434`。
- 僅允許 `https://omega-ten-20.vercel.app` 的指定跨來源請求；拒絕其他來源、錯誤 Host、不合法內容類型、超長請求與任意檔案路徑。
- 配對需要正式網站管理員的短期 AI 授權與本機頁面確認。完整網站登入 token 不會送到本機程式。
- AI 授權不能作為網站登入 token，不能直接讀寫網站資料。問題與文件不會出現在授權驗證請求中。
- 這台電腦只向固定正式站 `/api/local-ai/session` 驗證 AI 授權，不接受任意網址、不跟隨轉址、不使用系統 HTTP 代理轉送驗證。
- 配對能力與短期授權只存記憶體，不放 URL、檔案、瀏覽器永久儲存或紀錄。重啟即失效。
- 沿用網站原本的簽章登入；既有登入權限是快照，帳號權限變更不會即時撤銷所有既有 token。AI 授權限制 20 分鐘，必要時在本機解除配對或停止服務。
- 文件與模型答案以純文字顯示，不執行其中的指令。模型沒有修改資料的呼叫權限。
- 正式備註預覽使用 120 秒簽章內容，綁定登入與完整資料版本；適用多個 Vercel 工作程序。實際寫入用資料列鎖與交易核對版本，重播／衝突會拒絕；備註與稽核同時提交。
- 原有雲端工單圖片辨識屬於原網站功能，沒有被接進新助理，也沒有在本次測試呼叫。

## 驗證與回復

`start-ai.cmd --test` 只測隔離假資料並阻擋外部網路。部署 CI 安裝網站原有依賴後會追加 Flask 驗證；不需安裝到使用者系統。
測試包含來源／權限、配對核准與失效、拒絕非正式來源、授權不能當登入憑證、一般問題不送網站 API，以及確認重播／衝突。
實際登入與瀏覽器權限必須由你完成；自動測試使用假帳號驗證流程，不會代你讀密碼或操作真實客戶資料。

若需要立即停用新增的本機功能，先停止 `start-companion.cmd`；網站原有功能仍可使用。若需回退整個上線版本，應透過原 Vercel 部署紀錄回退已確認的上一版，不要清空資料庫或重設帳號。
