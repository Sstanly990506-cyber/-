# 營運功能修正

此文件描述本次程式變更；正式站是否已部署仍需確認。

| 項目 | 新行為 |
| --- | --- |
| 車趟 | 使用真實地址。設定道路服務才取得距離與時間，不再產生模擬座標。 |
| 毛利 | 工單可填「實際總成本」；毛利＝收入－實際成本。未知成本保持空白，不視為零。 |
| 完整資料 | 財務報表使用完整資料來源，保留主工單／客戶清單的分頁。LINE 固定統計跨全部頁數；AI 明細摘要有截斷標示。 |
| 財務第二密碼 | 後端核發 15 分鐘財務解鎖，應收／應付讀寫、財務資料與報表 API 均驗證。一般登入不預載財務資料。 |
| 登入撤銷 | 每次請求核對目前帳號及持久授權版本；改密碼、角色或模組權限會使既有登入失效，即使後來改回也不恢復舊登入。companion 短期票券也撤銷。 |
| 狀態與文件 | 發票選取僅納入已完成／已送出工單。文件區分隔離示範、已合併程式及正式部署驗收。月帳單包含待處理時仍排除取消工單。 |
| 稽核 | 工單 API 產生具 ID 的金額、狀態與成本修改紀錄，不依賴操作帳號能否開啟稽核模組。衍生應收由後端維護，工單、應收與稽核在同一交易／原子檔案替換提交。 |
| 財務帳號月帳單 | 財務解鎖後可唯讀取得客戶與工單依賴資料，不授予客戶／工單寫入權限。 |

## 道路服務設定

在伺服器／Vercel 設定 `GOOGLE_MAPS_API_KEY`，於 Google Cloud 啟用 **Routes API**，並啟用該專案的計費。金鑰限制至該 API；不可放在前端或提交到 GitHub。

只有使用者按下路線計算或手動確認時才向 Google 傳送站點地址，並產生 Google Maps Platform 計費。每次最多 24 個站點加工廠，矩陣最多 625 個元素。

7 站以下會比較符合「先送貨、後取貨」的全部順序；更多站點採逐站選擇較近路線，不能保證全域最短。道路時間為不含即時交通的預估值。調整路線後需再次確認，重新取得道路數據。

未設定金鑰時仍可排列地址與開啟 Google Maps，距離及時間顯示「尚未取得道路資料」。設定金鑰後若服務拒絕、地址無法定位或資料不完整，會顯示錯誤，不以模擬數字替代。較長路線拆成連續的 Google Maps 連結，避免超過網址可用的中途站限制。

## 上線影響

- 啟動時自動為 PostgreSQL `app_users` 加入 `session_version` 欄位。須保留既有服務的資料表變更權限。
- 舊版登入及 companion 票券缺少新驗證資料，更新後需重新登入及配對。
- 財務第二密碼變更會撤銷目前財務解鎖，但不撤銷一般登入。
- 舊工單不會自動產生成本；需要輸入實際成本後才顯示毛利。複製成新工單時不複製舊成本。
- 正式 PostgreSQL、Google Routes 服務與瀏覽器操作尚需部署後驗收；隔離測試不使用正式資料或外部 API。
