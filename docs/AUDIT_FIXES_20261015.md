# 營運流程與資料修正

版本 `20261015-audit-fixes-1` 保留原版首頁與配色，修正六項稽核中重現的問題，並在工單列表補上客戶名稱、「編輯」及「複製」入口。

| 問題 | 修正後行為 |
|---|---|
| 錯誤備份造成原資料清空 | 全部資料分類、列格式、ID 及 JSON 內容先驗證；PostgreSQL 的設定與資料在同一交易提交，失敗整次回復。本機檔案模式在寫入失敗時回復原檔。 |
| 舊畫面儲存覆蓋其他人的修改 | 每次儲存帶入原始版本，在交易鎖內重新核對；衝突回應 409，保留瀏覽器內的修改並提示重新載入。成功後更新版本，支援送出期間繼續編輯。 |
| 重複工號覆蓋應收款 | 後端在同一寫入鎖內檢查工號唯一性，帳款以固定 `orderId` 關聯；舊帳款在工號可明確對應時沿用原 ID 與已收金額。有歧義的舊帳款拒絕自動改寫。 |
| 確認 A 路線卻執行 B 工單 | 站點、類型或地址變動會使舊路線失效。最佳化和確認的非同步回應需仍符合目前站點；執行前要求有效且已確認的路線。 |
| 庫存 CSV 匯入錯位 | 支援逗號、換行與跳脫引號，整份先檢查欄位、品項與非負數值，再預覽並匯入；任何錯列都不會部分寫入。 |
| 首頁數字受列表分頁影響 | 新增依帳號權限計算的全體統計，與目前列表頁及搜尋分開；未解鎖財務顯示「待解鎖」，不以零代替未知資料。 |

車趟執行沿用同一套工單、帳款及稽核交易；刪除工單時也依固定 ID 刪除其自動應收款，避免誤刪同號的其他工單帳款。

上線後請重新整理頁面取得新程式。仍在使用舊程式的瀏覽器若未帶資料版本，後端會拒絕覆蓋既有資料；請先保留尚未儲存內容，再重新登入。

本次不批次修改正式歷史帳款，也不推測既有重號應如何拆帳。若遇到歧義提示，需要先核對原工單與已收款紀錄。

## 驗證

- Python 回歸案例涵蓋舊版本儲存、同毫秒版本更新、並行重號、舊帳款改號保留收款、刪除關聯、錯誤備份及還原失敗回復。
- PostgreSQL 五項回歸測試使用獨立 schema，確認實際鎖、交易回復、完整統計、財務權限，以及本機 AI 與表單同時修改時的鎖順序；CI 使用臨時 PostgreSQL 16 服務，透過 `AUDIT_TEST_DATABASE_URL` 啟用。未設定該變數的本機執行會跳過這五項。
- JavaScript 回歸案例涵蓋 CSV 特殊字元、錯列拒絕、版本遞進、衝突保留草稿，以及站點變動與過期非同步路線回應。
- Chromium 以完全隔離的 API 資料驗證首頁翻頁仍顯示 51、CSV 原檔往返、錯誤檔案拒絕、編輯／複製及正確車趟執行；320、390、768、1024、1440px 均無頁面溢出或操作按鈕互相重疊。
- 本機另以臨時 PostgreSQL 實際觸發寫入約束失敗，確認舊資料與設定皆保留。測試未使用正式資料庫或真實營運資料。
